# 自定义 GitHub 来源 V1 验证记录

2026-11-25，Apple Silicon Mac，macOS 27.3（26C5047e）。源码从主线 `1310ca1f` 开始实现。界面使用单独的 Developer ID 签名 Release 副本。首轮使用的临时主目录隔离了 Application Support，但仍与正式版共用来源偏好域。视觉 agent 已通过界面移除三条临时来源，并核对了偏好中的来源列表为空。

| 验证入口 | 输入与观察结果 |
| --- | --- |
| Core 发布线测试 | 检查 Stable、Preview、Nightly、同一基础版本的正式版、未识别 tag 和 Windows、Linux、Intel 文件名。文件名筛选按字面匹配。 |
| App 配置测试 | 保存后重新打开可读到发布线、文件名筛选和副本身份。另一条路径不会继承配置。移除一项关联后，另一条未知格式记录保留原始字节。 |
| 匿名 API 离线测试 | 通过 URLProtocol 观察到先查仓库，再按数字 ID 查发布。请求未携带 Cookie 和 Authorization。返回的说明保留为原生文本。 |
| ZIP 结构检查 | 普通包装目录下的唯一 App 可解包。同级带 PKG 的样本被拒绝。Ice 0.11.11 → 0.11.12 的真实 ZIP 包含 Sparkle 框架链接。首轮暴露临时目录规范路径差异，修正后通过签名和系统评估。 |
| 下载与验包 | 用真实 AltTab 11.10.2 ZIP 和 GitHub 发布摘要作为固定输入，通过下载代码的测试传输送入。与 11.10.1 已安装副本比对后通过签名、版本、架构和系统评估，暂存 App 带隔离标记。对相同字节改用错误摘要，会在解包前被阻止。 |
| 安装后回读 | 对临时目录中实际签名的 AltTab 版本对运行 App 回读。原路径未变、只把新版复制到别处时维持待手动完成。新版复制到原路径后确认 11.10.2，重开配置能读到原发布线与筛选。随后换成另一版本，记录要求复核。 |
| KeyRemap 正向样本 | 1.0.7 官方 ZIP 中的 AppleDouble 元数据曾被展开为额外资源，导致系统签名检查失败。修正解包后，真实下载包通过原有的签名检查。扫描回归测试另行确认，与另一份 App 版本相同时，指定关注的路径继续出现在扫描结果中。 |
| 本地化 | 按 Swift 编译器提取的实际键与字符串目录核对，并检查插值格式。 |

上述签名包检查没有启动候选 App。两组签名包都包含内建更新能力，因此这些结果覆盖检查器和回读逻辑；真实界面的归属判断另行体验。

## 独立 UI 体验

实现提交为 `0896b608` 和 `efb809c8`。视觉 agent 使用 standalone CUA 驱动在 900×600 工作台操作签名 Release：

- 从 AirCard 打开编辑器，查看了实际安装路径和 Bundle ID。切换 Stable、Preview 时，同版本正式版选项相应禁用或启用。
- 输入非 GitHub URL 并点验证，保存按钮保持禁用。第一轮的错误离输入框太远，灰色样式与普通说明接近。移近并加图标后，第二轮发现 490 pt 宽的编辑器截断了提示末尾。最终签名版本使用多行提示，视觉 agent 在相同窗口尺寸确认全文可见。[初版](./invalid-repository-before.png) · [修正版](./invalid-repository-after.png)
- 主机与 VM 首轮都遇到 GitHub 匿名配额耗尽。界面保留编辑内容、禁用保存，并告知可重试时间。
- 匿名配额恢复后，视觉 agent 通过工作台验证并保存 AirCard → Mak5er/AirCard，实际预览到 Stable 的 `v1.2.6` 和 `AirCard.dmg`，保存后可查看独立发布历史，更新仍由内建路线处理。该场景也暴露了同仓库、同版本时两份发布说明占用空间的问题。[保存后的工作台](./aircard-saved.png)
- 随后直接调用本版生产客户端，无凭据访问 GitHub，按仓库和资产数字 ID 下载 AltTab 11.10.2 的 4,885,500 字节 ZIP。确认发布摘要、隔离标记、目标版本、签名、架构和 Gatekeeper 均通过。该在线用例耗时 3.76 秒。
- 用户确认本版保留内建和个人两份说明的展示方式，记录为体验反馈。
- 把 KeyRemap 1.0.7 关联到用于反例的 `lwouis/alt-tab-macos`，保存文件名条件 `11.10.2`。灰色 Update 菜单成功下载真实的 AltTab ZIP，随后显示发布者或 Bundle ID 不匹配及红色 Blocked，制品没有本地交接入口。重新打开编辑器时筛选条件仍为 `11.10.2`。测试关联已通过 UI 移除。[身份不符的实测界面](./blocked.png)
- 在 900×600 窗口中，含多个 PR 链接和长哈希的原始 Markdown 占用了大部分说明区域。此版按方案以原生纯文本展示，保留这项可读性反馈。

- 正向流程使用单独的 QA Bundle ID、原 Developer ID 签名与独立偏好域。视觉 agent 在临时路径的 KeyRemap 1.0.6 上关注 Stable，下载并验证了公开的 1.0.7 ZIP，看到 Team 和 SHA-256 检查通过。[已验证制品](./keyremap-verified.png)
- 通过界面在 Finder 中显示已验证 App，复制到临时安装目录，点击 Finder 的替换按钮。工作台随后显示“Confirmed installation of 1.0.7.”，同机另一个同版副本与关注的副本均可见。QA 记录已清除待交接状态并记住 1.0.7。[Finder 替换](./keyremap-finder-replace.png) · [首次确认后的工作台](./keyremap-confirmed.png)
- 首次确认截图也记录了一个问题：确认后本地发布历史暂时消失，两个刷新入口同时出现。实际点击刷新又遇到 GitHub 限流。修正后，成功回读保留已有发布历史，无需再次访问 GitHub；遇到未经确认的副本变更仍会清除旧状态。对真实签名版本对执行的 App 状态回归已验证这两个结果；最后这项修正未重新进行视觉体验。视觉 agent 收尾时已核对正式和 QA 偏好域，测试关联及临时扫描路径均已清除。
